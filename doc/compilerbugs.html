Compiler bugs

The tracker for wrong-code and wrong-parse bugs in the C compiler: every bug fixed in this fork, and the known bugs still open. Most are inherited from the upstream cc65 2.19 base this SDK forked from.

1. How bugs are found and tracked

The compiler is under a standing correctness audit (design/LYNX_COMPILER_AUDIT_DESIGN.md): every test function is compiled at all four optimization levels (no -O, -O, -Oi, -Ors), executed on the headless GearLynx emulator, and its results are compared across levels and against the same source compiled with a host C compiler. Any disagreement is a compiler bug. The audit combines a directed test corpus (tests/compiler/corpus/), a random-program generator (lynxsmith), and mining of the fixes upstream cc65 made after the 2.19 release (tests/compiler/upstream/FIXES.md).

Every bug on this page has an execution-checked regression test that runs in CI (tests/run.sh). Open bugs live in tests/compiler/corpus/known/ marked known-bug; the harness expects them to fail, and the moment a fix lands it flags the stale marker so the entry moves to the fixed table below in the same change.

3. Known open bugs

None currently. When the audit confirms a new miscompile it gets an expected-to-fail regression in tests/compiler/corpus/known/, an upstream fix reference in tests/compiler/upstream/FIXES.md, and an entry here with a workaround until it is fixed.
