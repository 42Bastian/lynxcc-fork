abcrom Users Guide

abcrom is a standalone Lynx Game Development SDK utility that turns a tune into a runnable .lnx cartridge for auditioning in an emulator, with no toolchain at test time. It ships a pre-assembled template ROM — the snd sound engine plus a tiny boot harness — and patches a compiled tune stream into a reserved region, so a tune reaches a playable ROM in milliseconds. It is host-compiled and does not invoke cc65. Tunes are authored in ABC and compiled by abccc; for how the engine plays a stream, see the Sound page.

1. Overview

Once a tune is written, you usually want to hear it before wiring it into a game. abcrom gives that fast feedback loop: it takes an ABC tune (or an already-compiled stream) and produces a bootable .lnx that plays the tune on load in any Lynx emulator — no compile, no link, no cc65 installed. It is the preview companion to abccc, which does the actual ABC → stream compilation.

abcrom lives under tools/abcrom/ and its binary installs into the root bin/ alongside the rest of the SDK utilities. It shells out to abccc (which must be on PATH) to compile a tune, then does its own patching; pass --bin if the input is already a compiled stream.

2. How the template patcher works

abcrom ships a pre-assembled template ROM — the snd engine plus a tiny boot harness and four fixed, reserved tune regions — and simply patches a compiled stream into the region for a channel. Because the region is fixed-size, patching never changes the file length, so the .lnx header stays valid and a tune reaches a playable ROM in milliseconds.

Each region is fronted by an "ABCR" magic header carrying the format version, channel index, capacity and used length, so the patcher locates it without hard-coded offsets and refuses a template whose version does not match the compiler. On boot the harness calls snd_init() then snd_play() for each non-empty region and loops; an empty region is a single END byte and that channel stays silent.

3. Usage

abcrom is invoked with a tune and options:

abcrom  [opts]  tune.abc
  -o FILE          output .lnx (default: <tune>.lnx)
  -t FILE          template .lnx (default: bundled template)
  --channels MAP   place tunes on channels, e.g. 0:bass.abc,1:lead.abc
  --name STR       cart-name field in the .lnx header
  --run [EMU]      launch emulator after patching
  --bin            input is already a compiled stream, skip abccc

The simplest run patches one tune onto channel 0 and writes a ROM beside it:

        abcrom tune.abc                        # -> tune.lnx
        abcrom --channels 0:bass.abc,1:lead.abc -o song.lnx bass.abc
        abcrom --run tune.abc                   # patch, then launch an emulator

4. The template ROM

The template embeds a specific engine build and stream-format version. Its source lives in tools/abcrom/template/ and the bundled default tools/abcrom/template.lnx is committed, so abcrom works out of the box. Whenever the sound engine or the stream format changes, rebuild it once with the toolchain:

        make abcrom-template

The ABCR format-version byte turns a template/compiler mismatch into a hard error rather than silent corruption. Tunes larger than a region's capacity are rejected — bump the reserved size in the template source and rebuild. The patched .lnx carries the standard 64-byte header and runs in Handy, Mednafen and Felix; real-hardware carts need the encrypted micro-loader, a separate path outside abcrom's quick-preview scope.
