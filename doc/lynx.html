Atari Lynx specific information for cc65

An overview over the Atari Lynx runtime system as it is implemented for the cc65 C compiler.

1. Overview

This file contains an overview of the Atari Lynx runtime system as it comes with the cc65 C compiler. It describes the Lynx specific header files, available drivers, and any pitfalls specific to that platform. The memory map, C runtime stack and heap live on the separate Memory page, and the cart binary format, cart access and EEPROM save data on the Cart ROM and EEPROM page.

Please note that Lynx specific functions are just mentioned here, they are described in detail in the separate function reference. Even functions marked as "platform dependent" may be available on more than one platform. Please see the function reference for more information.

2. Platform specific header files

Programs containing Lynx specific code may use the lynx/lynx.h header file.

2.1. Lynx specific functions

These are declared in lynx/lynx.h and described in full in the function reference:

Cartridge access

openn, lynx_load, lynx_exec (see also Cart access).

EEPROM (cart save data)

The size-selectable read/write family — pick the variant matching the chip fitted to the cart (93C46 = 64 words, 93C66 = 256, 93C86 = 1024): eeprom_93c46_read / eeprom_93c66_read / eeprom_93c86_read and eeprom_93c46_write / eeprom_93c66_write / eeprom_93c86_write.

Sound

The compiled-stream music engine: snd_init, snd_play, snd_stop, snd_stop_channel, snd_pause, snd_continue, snd_active; plus the direct Mikey helpers mikey_snd_octave, mikey_snd_pitch, mikey_snd_taps, mikey_snd_integrate, mikey_snd_volume. See the dedicated Sound page for the engine guide and the abccc composing tutorial.

2.2. Hardware access

The following pseudo variables declared in the lynx/lynx.h header file do allow access to hardware located in the address space. Some variables are structures, accessing the struct fields will access the chip registers.

MIKEY

The MIKEY structure allows access to MIKEY chip. See the lynx/_mikey.h header file located in the include/lynx directory for the declaration of the structure.

SUZY

The SUZY structure allows access to SUZY chip. See the lynx/_suzy.h header file located in the include/lynx directory for the declaration of the structure.

_MIKEY_TIMERS

All eight Mikey timers as an array (mikey_timers[8]) based at $FD00, for code that walks the timers generically.

_HBL_TIMER, _VBL_TIMER, _UART_TIMER

Individual Mikey timers as single _mikey_timer structures: timer 0 — the horizontal-blank timer — at $FD00, timer 2 — the vertical-blank timer — at $FD08, and timer 4 — the UART baud timer — at $FD14.

_VIDDMA

The display-control / video-DMA word (dispctl) at $FD92.

2.3. Colour constants

lynx/lynx.h also defines the palette-index colour constants. They number the 16 entries of the default palette loaded by gfx_init:

COLOR_BLACK      0x00   COLOR_YELLOW      0x08
COLOR_RED        0x01   COLOR_LIGHTGREEN  0x09
COLOR_PINK       0x02   COLOR_GREEN       0x0A
COLOR_LIGHTGREY  0x03   COLOR_DARKBROWN   0x0B
COLOR_GREY       0x04   COLOR_VIOLET      0x0C
COLOR_DARKGREY   0x05   COLOR_BLUE        0x0D
COLOR_BROWN      0x06   COLOR_LIGHTBLUE   0x0E
COLOR_PEACH      0x07   COLOR_WHITE       0x0F

A matching set of GFX_COLOR_* aliases (for example GFX_COLOR_WHITE) is provided for use with the Lynx graphics functions; each GFX_COLOR_x is simply equal to the corresponding COLOR_x.

The joypad button and switch bit masks (JOY_UP_MASK and friends) and their convenience macros are documented on the Joypad input page.

3. Device support

This tree has no loadable drivers at all. Graphics and ComLynx serial are each provided as a static, smart-linked library, described below. Joypad input has its own Joypad input page, audio the dedicated Sound page, and EEPROM save data and cart data reading the Cart ROM and EEPROM page.

3.1. Graphics

Lynx graphics is a direct-call static library, not a loadable driver: there is exactly one display mode (160×102 in 16 colors) and all drawing is done by the Suzy sprite engine. No driver-install call is needed; just call gfx_init(). See design/LYNX_GFX_DESIGN.md for the design.

The library is implemented as an interrupt driven dual buffering device. To use it as a single-buffer device set draw page and view page to the same value 0 or 1;

Calling gfx_sprite(spr) will display a standard Lynx sprite on screen.

Calling gfx_flip() will do a flip screen (180-degree rotation for left-handed use).

Calling gfx_setbgcolor(bgindex) will set the text background color to the index defined by bgindex. If bgindex is 0 then the background color is transparent.

To set the framerate of the display hardware call gfx_setframerate(rate). The supported framerates are 50, 60 and 75 frames per second. Actually there is no real reason to use anything else than 75 frames per second.

To check if the drawing engine is busy with the previous swap you can call gfx_busy(). It returns 0 if idle and 1 if busy.

To update displays you can call gfx_updatedisplay(). It will wait for the next VBL interrupt and set the draw buffer to the view buffer. The draw buffer is also changed to (drawbuffer xor 1).

You can also enable or disable collision detection by a call to gfx_setcollisiondetection(active). The collision result is located before the sprite structure by default.

In order to reserve memory for the collision detection buffer you need to specify lynx-coll.cfg as the configuration file to the linker.

3.2. ComLynx serial

There is no loadable serial driver either: the ComLynx code is a static, smart-linked library (ser_open, ser_close, ser_get, ser_put, ser_status). Both directions are interrupt driven through 256-byte ring buffers. ser_close() disables the serial interrupts, stops the baud timer and drops buffered data. The SER_ERR_* codes are renumbered relative to stock cc65: always compare against the macros.

The ComLynx port has Tx and Rx wired together. Every byte is sent to all connected Lynxes. Only one Lynx can send at a time. There is no protocol created for communication. You are on your own.

If the Lynx returns framing error then it is likely that another Lynx is sending data at the same time.

The Lynx can also send a break and receive a break. The Lynx break is recognized if the bit is down for 24 bit cycles or more.

To send a break you just set the break bit. The length of the break depends on how long this bit is down.

The library supports the baudrates:

  • 62500

  • 31250

  • 9600

  • 7200

  • 4800

  • 3600

  • 2400

  • 1800

  • 1200

  • 600

  • 300

  • 150

  • 134.5

  • 110

  • 75

The parity bit supports MARK and SPACE. It also supports EVEN and ODD parity but the parity bit is included in the calculation. Most of us don't want it this way. But there is nothing we can do about it.

The Lynx hardware will always check parity on incoming traffic. Currently the library cannot receive data from standard PCs due to this parity bug. For working with Lynx to Lynx communication use EVEN parity.

To send data to standard PC's use MARK or SPACE as parity setting.

There is always only one stop bit. And the data length is always 8 bits.

We have no handshaking available. Even software handshake is impossible as ComLynx has only one wire for the data.

Both transmit and receive are interrupt driven.
